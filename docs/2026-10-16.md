# egl-fedora: RPM Epic Games Launcher с автообновлением и выбором Proton

Дата: 2026-10-16. Статус: реализация.

## Цель

Новичок на Fedora скачивает один RPM из GitHub Releases, устанавливает его и получает:

- Epic Games Launcher в меню, работающий на системных WebKitGTK, GTK 3 и libsoup 3;
- автоматические обновления без ручных действий;
- окно «Epic Games: выбор Proton», в котором можно выбрать Proton по умолчанию и отдельно для каждой игры (GE от Epic, DW-Proton, Proton-CachyOS, Proton из Steam и т. д.).

## Подтверждённое состояние (2026-10-16)

- Официальный AppImage: `https://launcher-public-service-prod06.ol.epicgames.com/launcher/api/installer/download/EpicGamesLauncher-x86_64.AppImage`, ответ 303 на `content-download-egs.distro.on.epicgames.com/Builds/EGLv2/<версия>/Linux/EpicGamesLauncher-x86_64.AppImage`.
- Текущая стабильная версия: `https://content-download-egs.distro.on.epicgames.com/Builds/EGLv2/stable-target.json` (`{"version":"0.96.1+ge3e236d","mode":"encouraged",...}`). Оба адреса доступны без авторизации.
- Подписи к AppImage публично нет (`.sig` отдаёт 403). Проверка: HTTPS, домен Epic, совпадение версии в пути редиректа и в бинарнике (`EpicGamesLauncher/<версия>`).
- Лаунчер это Tauri 2 + WebKitGTK 4.1. Ресурсы ищет в `<каталог бинарника>/../lib/epic-games-launcher`, EOS SDK по RUNPATH `$ORIGIN/../lib`. Встроенное самообновление поддерживает только .deb и AppImage (`SelfUpdate.LinuxFlavorUnsupported`).
- Proton: лаунчер качает один GE-Proton по пину Epic в `~/.local/share/com.epicgames.eglv2/compat/runtime/<версия>/` и запускает игру как `<runtime>/proton waitforexitandrun <exe> ...` с `STEAM_COMPAT_DATA_PATH=.../compatdata/<app_name>`. UI выбора нет, скрытая `EGL_PROTON_PIN` принимает только GE-Proton с GitHub GloriousEggroll.
- Подмена файла `proton` обёрткой проверена реальным запуском Zenless Zone Zero через DW-Proton: лаунчер не перекачивает runtime и запускает обёртку.
- Названия игр: `~/.local/share/com.epicgames.eglv2/cache/prod/catalog-cache.json`, `items.<itemId>.item.title`; установленные игры: `installations.jsonl` (последняя запись по `installationId`, без `deleted`).

## Принятые решения

- В релиз кладётся RPM с файлами лаунчера внутри (решение владельца, 2026-10-16). Риск: публичное распространение проприетарного ПО Epic и EOS SDK, возможен DMCA-запрос к репозиторию. README явно говорит, что проект неофициальный.
- Релизы создаёт GitHub Actions от `github-actions[bot]` как черновик; публикует владелец вручную (как в Tryx-Linux-GUI).
- Выбор Proton: отдельное окно GTK4 + libadwaita на Rust. Скачивания Proton в окне нет, только установленные версии и подсказка про ProtonPlus.
- Обновления на машине пользователя: системный таймер раз в час читает `SHA256SUMS` последнего опубликованного релиза, при более новой версии скачивает RPM, сверяет SHA256 и ставит через `dnf upgrade`.

## Архитектура

### Пакет `epic-games-launcher`

| Путь | Назначение |
|---|---|
| `/usr/bin/EpicGamesLauncher` | бинарник Epic из AppImage без изменений |
| `/usr/lib/libEOSSDK-Linux-Shipping.so`, `/usr/lib/epic-games-launcher/` | EOS SDK и ресурсы Tauri |
| `/usr/libexec/egl-fedora/egl-launch` | запуск из ярлыка: ставит перехват Proton и запускает лаунчер |
| `/usr/libexec/egl-fedora/egl-proton-hook` | ставит заглушку `proton` в каждый runtime Epic, оригинал сохраняет как `proton.epic` |
| `/usr/libexec/egl-fedora/egl-proton-router` | выбирает Proton по настройке и запускает его |
| `/usr/libexec/egl-fedora/egl-update` | проверка и установка обновления RPM |
| `/usr/bin/egl-proton` | окно «Epic Games: выбор Proton» |
| `egl-fedora-update.{service,timer}` | системный таймер обновлений, включён presets |
| `egl-fedora-proton-hook.{path,service}` | пользовательский юнит: при появлении нового runtime Epic ставит заглушку |

Версия RPM: `Version` = версия Epic (`0.96.1`), `Release` = `<ревизия упаковки>.git<хеш Epic>%{?dist}`. Ревизия упаковки хранится в `packaging/RELEASE` и поднимается при изменении нашего кода.

### Перехват Proton

1. Заглушка в `<runtime>/proton` вызывает роутер, если он установлен, иначе запускает `proton.epic`. После удаления пакета игры продолжают работать на GE от Epic.
2. Роутер читает `${XDG_CONFIG_HOME:-~/.config}/egl-fedora/proton.conf`:
   - `default=epic` или абсолютный путь к каталогу Proton;
   - `game.<app_name>=...` для отдельной игры (`app_name` = имя каталога префикса).
3. Для стороннего Proton с `protonfixes/` роутер задаёт `STORE=egs` и `UMU_ID` из `protonfixes/umu-database.csv` по `app_name` (иначе `umu-default`), чтобы применились фиксы игры. Для `epic` окружение не меняется.
4. Если выбранный Proton пропал, роутер пишет предупреждение в лог и запускает GE от Epic.
5. Лог: `${XDG_STATE_HOME:-~/.local/state}/egl-fedora/proton.log`.

Как пользователь находит выбор (решение 2026-10-16, ревизия 3):

- пункт «Выбрать Proton для игр» первой строкой в меню трея Epic. Его добавляет подменная `libayatana-appindicator3.so.1` из `/usr/lib64/egl-fedora/tray/` (`tray/egl-tray.c`): `egl-launch` ставит этот каталог первым в `LD_LIBRARY_PATH`, Tauri (tray-icon) грузит библиотеку трея через `dlopen` по имени и `dlsym`. Подменная библиотека определяет только `app_indicator_set_menu`, остальные функции `dlsym` находит в настоящей, подключённой зависимостью по абсолютному пути (`patchelf --replace-needed`); пункт добавляется только в процессе `EpicGamesLauncher`;
- действие «Выбрать Proton» у ярлыка Epic;
- уведомление при первом запуске каждой игры без своего выбора: «<игра> запущена через <Proton>» с кнопкой «Выбрать Proton» (маркер `${XDG_STATE_HOME}/egl-fedora/hint-shown/<app_name>`).

Отдельный пункт окна в меню приложений скрыт (`NoDisplay=true`) по решению владельца, после того как заработал трей. Ограничение: при автозапуске Epic (настройка «запуск вместе с системой») лаунчер стартует напрямую, без `egl-launch`, и пункта в трее нет.

Заглушка переустанавливается: при запуске лаунчера из ярлыка, при открытии окна и пользовательским path-юнитом, когда Epic создаёт новый runtime (ожидание завершения распаковки ограничено 15 минутами).

### CI и релизы

- `package.yml`: сборка RPM в контейнере актуальной Fedora (как в Tryx), скачивание официального AppImage, проверка версии, тесты скриптов, `cargo test`, rpmlint с фильтрами для бинарников Epic, проверка состава пакета. Запускается на push, PR и из `release.yml`.
- `release.yml`: по расписанию каждые 4 часа, вручную и при push в `main`. Определяет версию Epic и ревизию упаковки, тег `v<версия>-<ревизия>`. Если релиз с таким тегом уже есть (черновик или опубликованный), ничего не делает. Иначе собирает RPM, `SHA256SUMS`, attestation и создаёт черновик.

## Этапы

1. Скрипты Proton (hook, router, launch) и тесты на поддельных каталогах.
2. Updater, systemd-юниты, presets.
3. Окно `egl-proton` на Rust.
4. Spec, скрипт загрузки AppImage, архив исходников с vendored crates.
5. Локальная сборка, установка поверх текущего пакета, миграция настроек с `epic-dw-proton`, проверки.
6. Workflows. Создание репозитория на GitHub и push только с отдельного разрешения владельца.

## Критерии приёмки

- RPM собирается локально тем же скриптом, что и в CI; `rpm -V` чистый после установки.
- Лаунчер запускается из меню; ссылки `com.epicgames.launcher://` открываются им.
- Таймер обновлений включён после установки; `egl-update --check` корректно сообщает «обновлений нет» или версию.
- Окно показывает установленные Proton и игры, сохраняет выбор; роутер запускает выбранный Proton (проверено тестом и реальным запуском игры).
- После удаления пакета игры запускаются через GE от Epic.

## Риски и откат

- DMCA к репозиторию: решение владельца; при запросе релизы удаляются, пакет на машинах продолжает работать.
- Epic может изменить путь запуска Proton или начать проверять файлы runtime: тогда заглушка перестанет вызываться, игры пойдут через GE от Epic (без поломки).
- Автообновление через dnf из службы: при занятом dnf обновление откладывается до следующего запуска таймера.
- Откат: `sudo dnf remove epic-games-launcher` или установка предыдущего RPM из релизов (`dnf downgrade ./файл.rpm`); отключить автообновление: `sudo systemctl disable --now egl-fedora-update.timer`.

## Вне scope

- Скачивание Proton из окна.
- dnf-репозиторий или COPR.
- Подпись RPM ключом GPG.
- Сборки для Fedora, отличной от актуальной стабильной.
